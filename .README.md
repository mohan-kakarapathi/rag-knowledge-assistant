# RAG Knowledge Assistant

A Retrieval-Augmented Generation (RAG) application that allows users to upload documents and ask questions based on their content. The application retrieves relevant document chunks from a vector database and uses a Large Language Model (LLM) to generate context-aware answers.

## Features

- **Document Upload:** Upload supported documents for ingestion.
- **Text Extraction:** Extract text from PDF and text files.
- **Document Chunking:** Split documents into smaller chunks with configurable overlap.
- **Embeddings:** Generate vector embeddings using Google's Gemini embedding model.
- **Vector Storage:** Store document chunks and embeddings in ChromaDB.
- **Semantic Search:** Retrieve relevant chunks based on a user's question.
- **RAG-based Answers:** Generate answers using retrieved document context.
- **Document Replacement:** Re-upload a document with the same filename to replace its previous content.
- **REST API:** Expose functionality through FastAPI.
- **Interactive Frontend:** Use a Streamlit interface to interact with the application.

## Tech Stack

- **Language:** Python
- **Backend:** FastAPI
- **Frontend:** Streamlit
- **Vector Database:** ChromaDB
- **Embeddings:** `gemini-embedding-001`
- **LLM:** Google Gemini, configured through environment variables
- **Document Processing:** pypdf
- **Text Splitting:** LangChain text splitters

## Prerequisites

Install the following before running the project:

- Python 3.10 or a compatible version supported by the installed dependencies
- Git
- A Google Gemini API key
- pip, Python's package installer

Check your installed versions:

```bash
python --version
git --version
```

## Getting Started

### 1. Clone the repository

```bash
git clone https://github.com/YOUR_USERNAME/rag-knowledge-assistant.git
cd rag-knowledge-assistant
```

Replace `YOUR_USERNAME` with your GitHub username.

### 2. Create a virtual environment

**Windows (PowerShell):**

```powershell
python -m venv .venv
.venv\Scripts\Activate.ps1
```

If PowerShell blocks activation, you can use Command Prompt:

```bat
.venv\Scripts\activate.bat
```

**macOS / Linux:**

```bash
python3 -m venv .venv
source .venv/bin/activate
```

### 3. Install dependencies

```bash
python -m pip install --upgrade pip
pip install -r requirements.txt
```

### 4. Configure environment variables

Create a `.env` file in the project root directory.

```env
GEMINI_API_KEY=your_gemini_api_key
GENERATION_MODEL=gemini-3.5-flash-lite
LLM_TEMPERATURE=0
```

Use the exact variable names expected by `backend/app/config.py`. If your local configuration defines additional variables, add them as well.

Get a Gemini API key through Google AI Studio:

https://aistudio.google.com/

**Security:** Never commit `.env` or expose your API key in source code, screenshots, logs, or public repositories.

### 5. Start the backend

Run this command from the project root:

```bash
python -m uvicorn backend.app.main:app --reload
```

The FastAPI server should be available at:

http://127.0.0.1:8000

Open the interactive API documentation at:

http://127.0.0.1:8000/docs

### 6. Start the frontend

Open a second terminal, activate the same virtual environment, and run:

```bash
streamlit run frontend/app.py
```

Open the local URL displayed in the terminal, usually:

http://localhost:8501

Keep the backend running while using the frontend.

## How It Works

### Document Ingestion

1. The user uploads a supported document.
2. The backend extracts the document text.
3. The text is split into chunks using a configured chunk size and overlap.
4. Gemini generates embeddings for the chunks.
5. ChromaDB stores the chunks, embeddings, and metadata.

### Question Answering

1. The user submits a question.
2. The question is converted into an embedding.
3. ChromaDB retrieves relevant document chunks using semantic similarity.
4. The retrieved context is passed to the Gemini language model.
5. The model generates an answer grounded in the retrieved context.

### Document Replacement

When a document with an existing filename is uploaded again:

1. The new document is extracted and split into chunks.
2. New embeddings are generated.
3. Existing document IDs associated with the filename are identified.
4. The new chunks are stored under a new document ID.
5. Old chunks associated with the previous document IDs are deleted.

Preparing the new content before deleting the old content helps protect the existing document if text extraction or embedding generation fails. However, a storage or deletion failure during replacement may still require recovery or cleanup.

## Vector Database

ChromaDB uses persistent local storage in:

```text
data/chroma_db/
```

The collection is named:

```text
employee_handbook
```

Current ingestion settings:

| Setting | Value |
|---|---|
| Chunk size | 500 characters |
| Chunk overlap | 50 characters |
| Embedding model | `gemini-embedding-001` |
| Embedding dimensions | 768 |
| Similarity metric | Cosine distance |

These values reflect the current project configuration and can be changed as the application evolves.

The vector database is generated locally at runtime and should generally not be committed to GitHub.

## Troubleshooting

**Missing API key**

Check that `.env` exists in the project root and contains the correct key and variable names.

**Module import errors**

Run commands from the project root and ensure the virtual environment is activated.

**Backend fails to start**

Review the terminal traceback and verify that all dependencies are installed.

**No relevant search results**

Verify that the document was uploaded successfully and that the ChromaDB collection contains indexed chunks.

**Document replacement issues**

Check the ingestion logs and verify that old document IDs are deleted after the new chunks are stored.
